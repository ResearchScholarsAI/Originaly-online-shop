# Originaly — نسل بعدی فروشگاه اصالت

این نسخه، یک بازطراحی مستقل و تکامل‌یافته برای فروشگاه Originaly است که از نقاط قوت پروژه‌های ارسالی استفاده می‌کند اما هویت بصری، ساختار تجربهٔ کاربری و سیستم طراحی آن کاملاً جدید است.

## هویت طراحی

نام سیستم طراحی این نسخه **Obsidian Aurora** است: زمینهٔ مشکی-گرافیتی، نورپردازی ارغوانی/فیروزه‌ای، سبز اسیدی به‌عنوان رنگ کنش، کارت‌های شیشه‌ای، تصاویر editorial، تایپوگرافی فارسی Estedad و حرکت‌های کوتاه و طبیعی. هدف، ایجاد حس یک فروشگاه انتخاب‌شده و فرهنگی است، نه یک کاتالوگ شلوغ.

## قابلیت‌های حاضر

- صفحهٔ اصلی با hero سینمایی، معرفی کالکشن، editorial cards و ارزش‌های برند
- فروشگاه قابل فیلتر بر اساس دسته، جنسیت، جستجو و مرتب‌سازی قیمت
- صفحهٔ جزئیات محصول با گالری، سایز، موجودی، تخفیف، جزئیات و افزودن به سبد
- سبد خرید پایدار در `localStorage` با تغییر تعداد، حذف و محاسبهٔ هزینهٔ ارسال
- لیست علاقه‌مندی پایدار در `localStorage`
- Checkout فارسی با اطلاعات تحویل، روش پرداخت و رسید سفارش نمایشی
- طراحی کامل RTL و responsive برای موبایل، تبلت و دسکتاپ
- احترام به `prefers-reduced-motion`
- مسیرهای اصلی: `/`, `/shop`, `/product/:slug`, `/cart`, `/checkout`, `/wishlist`
- تست Vitest برای منطق catalog و تست موجود auth template

## وضعیت commerce

این انتشار برای **پیش‌نمایش عمومی و تست تجربهٔ خرید** آماده است. سبد، علاقه‌مندی و جریان checkout در سمت کاربر کار می‌کنند. برای شروع فروش واقعی باید در مرحلهٔ بعد:

1. جداول محصولات، سفارش‌ها، مشتریان، آدرس‌ها و موجودی به دیتابیس متصل شوند.
2. ثبت سفارش از Client به procedure سرور منتقل شود تا قیمت، موجودی و total در سرور محاسبه شود.
3. OTP واقعی با سرویس پیامک ایران متصل شود.
4. کلید و callback درگاه زرین‌پال در Secrets قرار گیرد.
5. callback پرداخت، idempotency، کنترل موجودی اتمیک و RLS تکمیل شود.
6. تصاویر محصول در storage پروژه یا CDN پایدار میزبانی شوند.

## اجرای محلی

```bash
pnpm install
pnpm dev
pnpm test
pnpm check
pnpm build
```

## استقرار فعلی

نسخهٔ build شده روی Netlify به‌صورت عمومی منتشر شده است:

- https://originaly-next-storefront.netlify.app/

پیش‌نمایش توسعهٔ Manus نیز در محیط پروژه فعال است و برای ادامهٔ توسعه به کار می‌رود.

## انتقال به WordPress در آینده

برای مهاجرت بدون دردسر، ساختار محصول مستقل از UI نگه داشته شده است. در انتقال آینده می‌توان فیلدهای `id`, `slug`, `name`, `brand`, `category`, `gender`, `price`, `compareAt`, `sizes`, `stock`, `image`, `gallery`, `description` و `details` را به WooCommerce mapping کرد. پیشنهاد معماری، نگه‌داشتن storefront مدرن به‌عنوان frontend و استفاده از WordPress/WooCommerce به‌عنوان backend/headless است؛ بنابراین لازم نیست طراحی حاضر کنار گذاشته شود.
