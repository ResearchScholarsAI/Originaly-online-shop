# راه‌اندازی Originaly روی WordPress و WooCommerce

## وضعیت واقعی

این مخزن شامل اپ React/TanStack SSR و یک **قالب نصب‌پذیر WordPress** (`wordpress/originaly-theme`) به‌همراه **افزونهٔ import کاتالوگ** (`wordpress/originaly-catalog-importer`) است. WooCommerce مسئول محصول، موجودی، سبد، checkout و سفارش WordPress می‌ماند.

**هیچ‌چیز در WordPress زنده نصب یا منتشر نشده است.** این نشست به دامنه/هاست/پنل سایت متصل نیست و کاربر هنوز برای خرید هاست آماده می‌شود؛ بستهٔ نصب‌پذیر آمادهٔ نصب در هاست مالک است.

## ساخت بسته‌ها

از ریشهٔ `storefront`:

```bash
npm run package:wordpress
```

خروجی‌ها در `artifacts/wordpress/`:

- `originaly-theme.zip` — پوستهٔ فارسی/RTL و responsive
- `originaly-catalog-importer.zip` — افزونهٔ انتقال محصول‌ها و تصاویر
- `Originaly-WordPress-Launch-Kit.zip` — پوسته، افزونه، کاتالوگ و چک‌لیست یکجا
- `woocommerce-product-data/ORIGINALY_IMPORT_REVIEW.csv` — ۷۲ کالا، با جداسازی صریح داده‌های قدیمی تأییدنشده

## نصب پس از خرید هاست

1. هاست Linux سازگار با WordPress، دامنه، دیتابیس پایدار، پشتیبان‌گیری، HTTPS/SSL، فضای ذخیرهٔ تصویر، ایمیل خروجی و cron فراهم کنید.
2. WordPress را نصب کنید؛ SSL را پیش از گردآوری اطلاعات مشتری فعال کنید. افزونهٔ رسمی WooCommerce را نصب و wizard را کامل کنید.
3. زبان، منطقهٔ زمانی، واحد پول/قیمت (تومان)، مالیات، ایمیل‌های فروشگاه و حساب مدیر را تنظیم کنید. قیمت‌های فعال برحسب تومان‌اند؛ پیش‌نمایش مبلغ را پیش از import کنترل کنید.
4. backup بگیرید و قالب `originaly-theme.zip` را از **نمایش ← پوسته‌ها ← افزودن ← بارگذاری پوسته** نصب و فعال کنید.
5. برای دیده‌شدن محصولات ناموجود، گزینهٔ WooCommerce **«مخفی‌کردن محصولات ناموجود از کاتالوگ»** باید خاموش باشد. افزونهٔ Originaly این گزینه را برای همین فروشگاه روی «نمایش» override می‌کند.
6. افزونهٔ `originaly-catalog-importer.zip` را نصب و فعال کنید. در **WooCommerce ← کاتالوگ Originaly** پیش‌نمایش و شمار را کنترل کنید: **۲۹ کالای تأییدشده** + **۴۳ کالای قدیمیِ در صف بررسی**.
7. فقط پس از اطمینان از واحد پول تومان، checkbox را تأیید و import را اجرا کنید. ۲۹ کالای تأییدشده به صورت **Draft** می‌مانند؛ ۴۳ مورد قدیمی منتشر می‌شوند، اما **قیمت ندارند، موجودی‌شان صفر است و سفارش نمی‌پذیرند**. صفحهٔ خانه دو بخش مستقل برای موجودها و آرشیو ناموجودها دارد.
8. بازبینی را یک‌به‌یک انجام دهید. در جدول مدیریتی، قیمت/سایز قدیمی صرفاً یادداشت مرجع و «تأییدنشده» است. در صورت راستی‌آزمایی عکس، مدل، برند، قیمت روز، یک سایز و موجودی فیزیکی، آن مقادیر را در ویرایشگر WooCommerce تکمیل کنید؛ فقط محصولی که قیمت، موجودی و یک سایز واقعی دارد قابل خرید خواهد شد.
9. مالک روش حمل/پس‌کرایه و هزینهٔ واقعی آن، درگاه و callback/verify، سیاست حریم‌خصوصی/مرجوعی/شرایط فروش، پیامک OTP، اطلاعات تماس و قوانین محلی را تعیین کند. کلیدها فقط از راه امن روی هاست ذخیره شوند؛ این بسته هیچ credential ندارد.
10. فروشگاه را در staging یا maintenance mode نگه دارید؛ سفارش آزمایشی و callback، لغو، خطا، refund، موجودی، حمل و ایمیل را بررسی کنید. فقط پس از آزمون، محصولات تأییدشده را منتشر کنید.

## دامنه و SEO

پس از اتصال دامنه، آدرس عمومی WordPress را تنظیم کنید. پیوندهای یکتا، صفحات Shop/Cart/Checkout/My Account، sitemap، robots.txt، metadata، canonical، Open Graph و HTTPS را بررسی کنید.

## محدودیت‌ها

- تا خرید/اتصال هاست، نصب مستقیم و آزمون سایت زنده ممکن نیست؛ نشست به پنل WordPress مالک متصل نیست.
- بسته‌های قابل‌نصب و پیش‌نمایش محلی جایگزین آزمون نهایی در دامنه و حساب میزبانی مالک نیستند.
- پرداخت آنلاین/زرین‌پال، OTP، حمل، مالیات، policyهای مرجوعی و دادهٔ تماس به سرویس واقعی متصل نشده‌اند؛ فروش زنده تا اتصال و آزمون این موارد آماده نیست.
- قیمت/سایز ۴۳ محصول قدیمی فقط با نشان عدم‌تأیید در گزارش مدیریتی آمده‌اند و به‌عنوان قیمت جاری یا موجودی قابل سفارش استفاده نمی‌شوند.
- هیچ راهکار فنی نمی‌تواند صفرخطا روی هاست/درگاهِ هنوز نصب‌نشده را تضمین کند؛ چک‌لیست آزمون پیش از فروش واقعی الزامی است.
